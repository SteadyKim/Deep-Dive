# 프로세스 간 통신

## 개요

프로세스는 기본적으로 서로 독립된 메모리 공간을 가집니다.  
한 프로세스가 자신의 변수에 값을 써도, 다른 프로세스는 그 값을 볼 수 없습니다.  
이 격리는 안정성과 보안을 위해 꼭 필요하지만, 동시에 **여러 프로세스가 협력해서 하나의 일을 하려면 데이터를 주고받을 방법**이 필요하다는 문제를 만듭니다.

이처럼 서로 다른 프로세스가 데이터를 교환하거나 동작을 조율하는 방법이 `프로세스 간 통신(IPC, Inter-Process Communication)`입니다.  
여기서 다루는 것은 "공유 자원에 대한 접근을 어떻게 막을 것인가(동기화)"가 아니라, **애초에 격리된 프로세스가 어떤 통로로 데이터를 주고받을 것인가**입니다.

## 왜 IPC가 필요한가

프로세스를 격리하면 하나가 죽어도 다른 프로세스에 영향을 주지 않고, 잘못된 접근으로 남의 메모리를 망가뜨릴 수도 없습니다.  
하지만 현실의 프로그램은 혼자 동작하지 않습니다.

- 웹 서버 프로세스가 별도의 로그 수집 프로세스에게 로그를 넘긴다.
- 셸에서 `ls | grep txt`처럼 한 명령의 출력이 다른 명령의 입력이 된다.
- 브라우저의 렌더링 프로세스와 네트워크 프로세스가 데이터를 주고받는다.

이 모든 경우, 격리된 프로세스 사이를 잇는 **명시적인 통로**가 필요합니다.  
IPC는 크게 두 가지 방식으로 나눌 수 있습니다.

- `공유 메모리(Shared Memory)`: 여러 프로세스가 같은 메모리 영역을 함께 바라보는 방식
- `메시지 전달(Message Passing)`: 커널을 통해 데이터를 복사해 주고받는 방식

이 두 갈래를 기준으로 대표적인 IPC 기법들을 살펴보겠습니다.

## 1. 공유 메모리

### 공유 메모리란 무엇인가

`공유 메모리`는 서로 다른 프로세스가 **같은 물리 메모리 영역을 각자의 주소 공간에 매핑해서 함께 사용하는** 방식입니다.  
한 프로세스가 그 영역에 값을 쓰면, 다른 프로세스는 즉시 같은 값을 읽을 수 있습니다.

동작을 단순화하면 다음과 같습니다.

1. 한 프로세스가 커널에 공유 메모리 영역을 요청해 생성합니다.
2. 통신에 참여할 프로세스들이 그 영역을 자신의 주소 공간에 붙입니다.
3. 이후에는 커널을 거치지 않고 그냥 메모리를 읽고 쓰는 것처럼 데이터를 주고받습니다.

### 공유 메모리의 특징

- **빠릅니다.** 데이터를 복사하지 않고 같은 메모리를 직접 보기 때문에, 대량의 데이터를 주고받을 때 가장 빠른 축에 속합니다.
- **동기화가 별도로 필요합니다.** 커널이 접근 순서를 조정해 주지 않으므로, 누가 언제 쓰고 읽는지는 프로세스들이 직접 맞춰야 합니다.

바로 이 지점에서 IPC와 동기화가 만납니다.  
공유 메모리는 "통로"만 제공할 뿐이고, 그 통로에서 발생하는 `Race Condition`은 `뮤텍스`나 `세마포어` 같은 동기화 도구로 따로 막아야 합니다.

즉, 공유 메모리는 **가장 빠르지만 가장 손이 많이 가는** 방식입니다.

## 2. 메시지 전달


`메시지 전달`은 프로세스가 커널이 제공하는 통로를 통해 **데이터를 메시지 단위로 주고받는** 방식입니다.  
공유 메모리와 달리 각 프로세스는 자신의 메모리만 사용하고, 데이터는 커널을 거쳐 복사되어 전달됩니다.

기본 연산은 보통 두 가지입니다.

- `send`: 메시지를 보냅니다.
- `receive`: 메시지를 받습니다.

### 메시지 전달의 특징

- **안전합니다.** 프로세스끼리 메모리를 직접 공유하지 않으므로, 한쪽의 실수가 다른 쪽 메모리를 망가뜨릴 위험이 적습니다.
- **동기화가 상대적으로 쉽습니다.** 커널이 송수신을 중개하므로, 개발자가 직접 lock을 걸지 않아도 되는 경우가 많습니다.
- **상대적으로 느릴 수 있습니다.** 데이터가 커널을 거쳐 복사되기 때문에, 대량 데이터에서는 공유 메모리보다 오버헤드가 큽니다.

정리하면, 메시지 전달과 공유 메모리는 다음과 같은 트레이드오프를 가집니다.

| 구분 | 공유 메모리 | 메시지 전달 |
| --- | --- | --- |
| 데이터 전달 | 같은 메모리를 직접 접근 | 커널을 거쳐 복사 |
| 속도 | 빠름 | 상대적으로 느림 |
| 동기화 부담 | 직접 처리해야 함 | 커널이 상당 부분 중개 |
| 안전성 | 실수 시 위험 | 격리가 잘 유지됨 |

## 3. 대표적인 IPC 기법

앞의 두 방식을 바탕으로, 실제 운영체제에서 자주 쓰이는 기법들을 살펴보겠습니다.

### 파이프

`파이프(Pipe)`는 한 프로세스의 출력을 다른 프로세스의 입력으로 연결하는 **단방향 통신 통로**입니다.

- `익명 파이프(Anonymous Pipe)`: 보통 부모-자식처럼 **관련 있는 프로세스** 사이에서만 사용됩니다. 셸의 `ls | grep txt`가 대표적인 예입니다.
- `명명 파이프(Named Pipe, FIFO)`: 파일 시스템에 이름을 가진 형태로 존재해서, **서로 관련 없는 프로세스** 사이에서도 통신할 수 있습니다.

파이프는 단순하고 직관적이지만, 기본적으로 단방향이고 데이터가 바이트 스트림 형태로 흐른다는 특징이 있습니다.

### 메시지 큐

`메시지 큐(Message Queue)`는 커널이 관리하는 큐에 메시지를 넣고 빼는 방식입니다.

- 보낸 쪽과 받는 쪽이 동시에 살아 있지 않아도, 큐에 메시지가 남아 있어 나중에 받을 수 있습니다.
- 메시지에 타입을 부여해, 받는 쪽이 원하는 종류의 메시지만 골라 읽을 수도 있습니다.

파이프가 단순한 바이트 흐름이라면, 메시지 큐는 **경계가 있는 메시지 단위**로 데이터를 다룬다는 점이 다릅니다.

### 공유 메모리

앞서 설명한 공유 메모리도 대표적인 IPC 기법입니다.  
가장 빠르지만 동기화를 직접 해야 하므로, 보통 세마포어 같은 동기화 도구와 함께 묶어서 사용합니다.

### 소켓

`소켓(Socket)`은 네트워크를 통해 데이터를 주고받는 통신 종단점입니다.

- **다른 컴퓨터**에 있는 프로세스와도 통신할 수 있다는 점이 다른 기법과 크게 구별됩니다.
- 같은 컴퓨터 안의 프로세스끼리 통신하는 `유닉스 도메인 소켓(Unix Domain Socket)`도 있어, 로컬 IPC 용도로도 널리 쓰입니다.

소켓은 범용성이 매우 높아, 웹 서버와 클라이언트처럼 물리적으로 떨어진 프로세스 간 통신의 사실상 표준입니다.

### 시그널

`시그널(Signal)`은 프로세스에게 특정 사건이 발생했음을 알리는 **간단한 비동기 알림**입니다.

- 데이터를 주고받기보다는, "종료해라", "중단해라" 같은 **짧은 신호를 전달**하는 데 쓰입니다.
- `Ctrl + C`를 눌렀을 때 실행 중인 프로세스에 전달되는 것이 대표적인 시그널입니다.

시그널은 풍부한 데이터를 옮기는 통로라기보다, 이벤트를 알리는 가벼운 수단에 가깝습니다.

## 4. 언제 무엇을 쓰는가

IPC 기법은 이름으로 외우기보다, **주고받을 데이터의 양과 프로세스의 위치**를 기준으로 고르는 것이 자연스럽습니다.

### 많은 데이터를 아주 빠르게 주고받아야 할 때

같은 컴퓨터 안에서 대량의 데이터를 최소한의 오버헤드로 공유해야 한다면 `공유 메모리`가 유리합니다.  
단, 동기화를 직접 책임져야 한다는 비용을 감수해야 합니다.

### 단순한 스트림 연결이면 충분할 때

한 프로세스의 출력을 다른 프로세스의 입력으로 잇는 정도라면 `파이프`가 가장 간단합니다.  
셸 명령 조합이 대표적인 예입니다.

### 경계가 있는 메시지를 안전하게 주고받을 때

메시지 단위로 데이터를 관리하고, 송수신 타이밍을 느슨하게 두고 싶다면 `메시지 큐`가 적합합니다.

### 다른 컴퓨터의 프로세스와 통신할 때

물리적으로 떨어진 프로세스와 통신해야 한다면 `소켓`이 사실상 유일한 선택입니다.  
로컬 통신에도 유닉스 도메인 소켓으로 폭넓게 활용됩니다.

### 짧은 알림만 필요할 때

데이터가 아니라 "이 사건이 발생했다"는 신호만 전달하면 되는 경우에는 `시그널`이 가볍고 적절합니다.

## 정리

- `프로세스 간 통신(IPC)`은 서로 독립된 메모리를 가진 프로세스들이 데이터를 주고받거나 동작을 조율하는 방법입니다.
- IPC는 크게 같은 메모리를 함께 보는 `공유 메모리` 방식과, 커널을 거쳐 데이터를 복사하는 `메시지 전달` 방식으로 나뉩니다.
- `공유 메모리`는 가장 빠르지만 동기화를 직접 해야 하고, `메시지 전달`은 안전하지만 복사 오버헤드가 있습니다.
- 대표 기법으로는 `파이프`, `메시지 큐`, `공유 메모리`, `소켓`, `시그널`이 있으며, 각각 데이터의 양·방향·프로세스의 위치에 따라 쓰임이 다릅니다.
- IPC는 "통로"를 제공할 뿐이고, 그 통로에서 발생하는 접근 순서 문제는 `프로세스 동기화`의 영역입니다.

결국 IPC의 본질은 **안정성을 위해 격리한 프로세스들을, 필요할 때 안전하게 이어 주는 통로를 어떻게 설계할 것인가**에 있습니다.  
그리고 공유 메모리, 메시지 전달, 그리고 그 위에서 파생된 여러 기법들은 이 문제를 서로 다른 속도와 안전성의 균형점에서 해결하기 위한 도구들입니다.
