# 3가지 조인 알고리즘

## 개요

데이터베이스에서 조인은 실행 비용을 크게 좌우하는 핵심 연산입니다.  
같은 결과를 반환하는 SQL이라도 어떤 조인 알고리즘을 선택하느냐에 따라 응답 시간과 I/O 패턴, 메모리 사용량이 크게 달라질 수 있습니다.

대표적인 조인 알고리즘은 다음 3가지입니다.

- `Nested Loop Join`
- `Hash Join`
- `Sort Merge Join`

이 세 가지를 이해할 때는 단순히 "무엇이 빠른가"가 아니라, **데이터 양**, **인덱스 유무**, **조인 조건의 형태**, **정렬 비용**, **메모리 여유**를 함께 봐야 합니다.

## 조인 알고리즘을 보는 기준

조인 알고리즘은 보통 다음 기준으로 비교합니다.

- 작은 건수에 빠르게 응답해야 하는가
- 대량 데이터를 한 번에 처리해야 하는가
- 조인 조건이 `=` 인가, 아니면 범위 조건인가
- 인덱스를 활용할 수 있는가
- 메모리 사용량과 정렬 비용을 감당할 수 있는가

즉, 각 알고리즘은 절대적인 우열 관계가 아니라 **상황별로 강점이 다른 전략**입니다.

## 1. Nested Loop Join (NLJ)

### 원리

`Nested Loop Join`은 프로그래밍의 이중 `for` 문과 유사합니다.  
외부 테이블(`Driving Table`)에서 한 건을 읽을 때마다, 내부 테이블(`Driven Table`)에서 조인 대상을 반복적으로 찾습니다.

내부 테이블 접근 방식은 크게 두 가지입니다.

- 내부 테이블 전체를 다시 읽는 방식
- 내부 테이블 인덱스를 통해 필요한 행만 찾는 방식

실무에서는 두 번째 방식이 일반적이며, 이 경우 외부 테이블에서 읽은 키 값으로 내부 테이블 인덱스를 반복 탐색합니다.

### 장점

- 인덱스가 잘 구성되어 있으면 소량 데이터 조회에 매우 빠릅니다.
- 첫 결과를 빠르게 반환할 수 있어 응답 속도가 중요한 `OLTP` 환경에 유리합니다.
- 외부 집합이 작을수록 효율이 좋습니다.

### 단점

- 외부 테이블에서 읽는 건수가 많아질수록 내부 테이블 탐색 횟수가 급격히 증가합니다.
- 내부 인덱스를 반복 탐색하면서 `랜덤 I/O`가 많이 발생합니다.
- 대용량 조인에서는 성능이 급격히 나빠질 수 있습니다.
- 애플리케이션 레벨에서는 흔히 `N+1` 문제의 원인이 되는 접근 방식과 구조적으로 닮아 있습니다.

### 유리한 상황

- 외부 테이블 결과 건수가 매우 적을 때
- 내부 테이블 조인 컬럼에 적절한 인덱스가 있을 때
- 부분 범위 처리와 빠른 첫 응답이 중요할 때

## 2. Hash Join (HJ)

### 원리

`Hash Join`은 보통 더 작은 입력 집합을 먼저 읽어 메모리(`PGA`)에 해시 테이블을 만드는 `Build` 단계와, 더 큰 입력 집합을 읽으면서 해시 테이블에서 매칭 대상을 찾는 `Probe` 단계로 구성됩니다.

흐름은 다음과 같습니다.

1. 작은 테이블을 읽어 조인 키 기준 해시 테이블 생성
2. 큰 테이블을 순차적으로 스캔
3. 각 행의 조인 키로 해시 테이블을 탐색해 매칭

즉, 인덱스를 반복적으로 타는 대신 메모리 기반 매칭으로 대량 데이터를 처리하는 방식입니다.

### 장점

- 대용량 데이터 조인에 매우 강합니다.
- `랜덤 I/O`보다 `순차 I/O` 중심으로 동작해 대량 처리에 효율적입니다.
- 적절한 메모리가 확보되면 매우 빠르게 동작합니다.
- `DW`, 리포팅, 배치 처리처럼 많은 데이터를 읽는 환경에서 자주 유리합니다.

### 단점

- 조인 조건이 기본적으로 `동등 조인(=)` 이어야 효과적으로 사용할 수 있습니다.
- 해시 테이블을 담을 메모리가 부족하면 `Temp` 영역으로 넘기는 `Spill to Disk`가 발생할 수 있습니다.
- 디스크 스필이 발생하면 성능이 크게 떨어집니다.
- 첫 결과를 즉시 반환하는 특성은 `Nested Loop Join`보다 약한 편입니다.

### 유리한 상황

- 조인 대상 데이터가 많을 때
- 동등 조인 조건일 때
- 인덱스 효율이 낮거나, 인덱스를 타는 것보다 전체 스캔이 더 유리할 때
- 충분한 `PGA` 메모리를 확보할 수 있을 때

## 3. Sort Merge Join (SMJ)

### 원리

`Sort Merge Join`은 조인할 두 입력 집합을 각각 조인 키 기준으로 먼저 정렬한 뒤, 정렬된 두 집합을 순차적으로 읽으며 병합하는 방식입니다.

흐름은 다음과 같습니다.

1. 양쪽 입력 집합을 조인 키 기준으로 정렬
2. 정렬된 결과를 앞에서부터 비교
3. 키 값이 맞는 구간을 순차적으로 병합

즉, 조인을 위해 먼저 정렬 비용을 지불하고, 이후 병합 단계에서 효율적으로 매칭하는 전략입니다.

### 장점

- `BETWEEN`, `>`, `<` 같은 `비동등 조인`에서도 활용할 수 있습니다.
- `Hash Join`처럼 대량 처리에 적합하며 `랜덤 I/O`가 적습니다.
- 양쪽 입력이 이미 정렬되어 있거나 인덱스를 통해 정렬된 상태로 읽을 수 있다면 매우 강력한 대안이 됩니다.

### 단점

- 정렬 자체가 무거운 작업이라 `CPU`와 메모리를 많이 사용합니다.
- 정렬 대상이 크면 `Temp` 사용량이 커질 수 있습니다.
- 단순 동등 조인에서는 보통 `Hash Join`보다 비효율적일 수 있습니다.

### 유리한 상황

- 비동등 조인이 필요할 때
- 양쪽 입력이 이미 정렬된 상태이거나 정렬 비용이 낮을 때
- 대량 데이터를 순차적으로 처리해야 할 때

## 한눈에 비교

| 항목 | Nested Loop Join | Hash Join | Sort Merge Join |
| --- | --- | --- | --- |
| 기본 원리 | 외부 건수만큼 내부 반복 탐색 | 작은 집합 해시 테이블 생성 후 큰 집합 탐색 | 양쪽 정렬 후 병합 |
| 유리한 데이터 규모 | 소량 데이터 | 대량 데이터 | 대량 데이터 |
| 주요 I/O 패턴 | 랜덤 I/O | 순차 I/O 중심 | 순차 I/O 중심 |
| 인덱스 의존성 | 높음 | 낮음 | 상황에 따라 활용 |
| 조인 조건 | 동등 조인에 주로 강함 | 동등 조인에 강함 | 동등/비동등 조인 가능 |
| 첫 응답 속도 | 매우 빠름 | 상대적으로 느릴 수 있음 | 정렬 비용 때문에 느릴 수 있음 |
| 주요 리스크 | 반복 탐색 폭증 | 메모리 부족 시 디스크 스필 | 정렬 비용 과다 |
| 대표 사용 환경 | `OLTP` | `DW`, 배치 | 대량 범위 조인, 정렬 기반 처리 |

## 어떤 알고리즘을 선택해야 하는가

옵티마이저는 일반적으로 다음 요소를 종합해 조인 방식을 선택합니다.

- 예상 결과 건수
- 조인 컬럼 인덱스 존재 여부
- 테이블 크기와 데이터 분포
- 메모리 사용 가능량
- 조인 조건이 동등 조건인지 여부

실무적으로는 다음처럼 이해하면 편합니다.

- **소량 + 인덱스 존재 + 빠른 응답 필요**: `Nested Loop Join`
- **대량 + 동등 조인 + 메모리 확보 가능**: `Hash Join`
- **대량 + 비동등 조인 또는 정렬 상태 활용 가능**: `Sort Merge Join`

## 정리

- `Nested Loop Join`은 소량 데이터를 빠르게 찾는 데 강하지만, 대량 처리에서는 반복 탐색 비용이 커집니다.
- `Hash Join`은 대량 동등 조인에 매우 강력하지만, 메모리가 부족하면 성능이 급격히 떨어집니다.
- `Sort Merge Join`은 정렬 비용이 크지만, 비동등 조인이나 정렬된 입력을 활용할 때 좋은 선택이 됩니다.
- 결국 조인 알고리즘은 하나가 항상 우월한 것이 아니라, **데이터 양과 접근 경로, 메모리 조건에 따라 최적 해법이 달라지는 실행 전략**입니다.
