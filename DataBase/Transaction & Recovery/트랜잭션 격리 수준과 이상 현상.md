# 트랜잭션 격리 수준과 이상 현상

## 개요

트랜잭션 격리 수준은 동시에 실행되는 여러 트랜잭션이 서로의 작업에 어느 정도까지 영향을 줄 수 있는지를 정의하는 기준입니다.  
격리 수준이 낮을수록 동시성은 높아지지만 데이터 부정합 가능성이 커지고, 격리 수준이 높을수록 정합성은 좋아지지만 성능 비용이 증가합니다.

격리 수준을 이해하려면 먼저 격리 수준이 충분히 보장되지 않을 때 발생하는 대표적인 이상 현상을 알아야 합니다.

## 이상 현상

### Dirty Read

`Dirty Read`는 트랜잭션이 아직 커밋하지 않은 데이터를 다른 트랜잭션이 읽는 현상입니다.  
이후 원본 트랜잭션이 롤백되면, 읽은 쪽은 실제로 존재하지 않는 데이터를 기준으로 작업하게 됩니다.

### Non-Repeatable Read

`Non-Repeatable Read`는 하나의 트랜잭션 안에서 동일한 데이터를 두 번 조회했을 때 결과가 달라지는 현상입니다.  
보통 첫 번째 조회와 두 번째 조회 사이에 다른 트랜잭션이 해당 데이터를 수정하고 커밋했을 때 발생합니다.

### Phantom Read

`Phantom Read`는 하나의 트랜잭션 안에서 동일한 조건으로 범위 조회를 두 번 수행했을 때, 처음에는 없던 행이 두 번째 조회에서 나타나는 현상입니다.  
기존 행의 값 변경이 아니라 조건에 맞는 새로운 행이 삽입되어 결과 집합 자체가 달라지는 것이 핵심입니다.

## 트랜잭션 격리 수준 4단계

### 1. Read Uncommitted

가장 낮은 격리 수준입니다. 각 트랜잭션의 변경 내용이 커밋이나 롤백 여부와 상관없이 다른 트랜잭션에 보일 수 있습니다.

#### 메커니즘

쓰기 작업 시 최소한의 잠금만 사용하고, 읽기 작업은 잠금을 거의 사용하지 않습니다.  
그 결과 읽기 성능은 높을 수 있지만 데이터 정합성은 매우 낮습니다.

#### 특징

- `Dirty Read`가 발생할 수 있습니다.
- `Non-Repeatable Read`가 발생할 수 있습니다.
- `Phantom Read`가 발생할 수 있습니다.
- 일반적인 업무 시스템에서는 거의 사용하지 않습니다.

### 2. Read Committed

대부분의 데이터베이스 시스템에서 기본으로 사용하는 격리 수준입니다. 다른 트랜잭션은 커밋이 완료된 데이터만 읽을 수 있습니다.

#### 메커니즘

읽기 시점마다 커밋된 최신 버전의 데이터를 조회합니다.  
예를 들어 오라클은 데이터가 변경 중일 때 언두 영역에 저장된 변경 전 데이터를 읽어 일관성을 유지합니다. 이 방식은 읽기 작업이 쓰기 작업을 오래 기다리지 않게 하면서도 `Dirty Read`를 방지합니다.

#### 특징

- `Dirty Read`는 방지됩니다.
- 한 트랜잭션 안에서 같은 쿼리를 다시 실행할 때, 그 사이 다른 트랜잭션이 커밋한 변경이 반영될 수 있습니다.
- 따라서 `Non-Repeatable Read`와 `Phantom Read`는 여전히 발생할 수 있습니다.

### 3. Repeatable Read

한 트랜잭션 안에서 한 번 조회한 데이터는 트랜잭션이 끝날 때까지 동일한 내용으로 다시 읽을 수 있도록 보장하는 수준입니다.

#### 메커니즘

일반적으로 트랜잭션 시작 시점의 스냅샷을 기준으로 조회를 수행합니다.  
현재 버전이 이 스냅샷보다 늦게 커밋된 데이터라면, DBMS는 언두 정보나 과거 버전을 참조해 일관된 조회 결과를 재구성합니다.

#### 특징

- `Dirty Read`는 방지됩니다.
- `Non-Repeatable Read`는 방지됩니다.
- 기존에 읽은 행에 대한 일관성은 높아지지만, 범위 조건에 맞는 새로운 행 삽입까지 항상 막는 것은 아닙니다.
- 따라서 일반적으로 `Phantom Read`는 발생할 수 있습니다.
- 다만 MySQL InnoDB는 넥스트 키 락 같은 메커니즘으로 이 수준에서 팬텀 리드를 일부 억제합니다.

### 4. Serializable

가장 엄격한 격리 수준으로, 여러 트랜잭션을 마치 순차적으로 하나씩 실행한 것과 같은 결과를 보장합니다.

#### 메커니즘

읽기 작업도 단순 조회로 끝나지 않고, 조회한 데이터나 범위 전체에 대한 제어를 수행합니다.  
DBMS에 따라 공유 락으로 범위를 잠그거나, 스냅샷 기반 검증을 통해 직렬 실행과 충돌하는 작업을 실패시킵니다.

#### 특징

- `Dirty Read`를 방지합니다.
- `Non-Repeatable Read`를 방지합니다.
- `Phantom Read`를 방지합니다.
- 정합성은 가장 높지만 잠금 경합, 대기, 재시도 비용이 커져 동시 처리 성능이 크게 떨어질 수 있습니다.

## 격리 수준별 발생 현상 요약

| 격리 수준 | Dirty Read | Non-Repeatable Read | Phantom Read |
| --- | --- | --- | --- |
| Read Uncommitted | 발생 | 발생 | 발생 |
| Read Committed | 방지 | 발생 | 발생 |
| Repeatable Read | 방지 | 방지 | 발생 |
| Serializable | 방지 | 방지 | 방지 |

## 정리

- 트랜잭션 격리 수준은 동시성과 데이터 정합성 사이의 균형을 결정합니다.
- 격리 수준이 낮을수록 성능에는 유리하지만 `Dirty Read`, `Non-Repeatable Read`, `Phantom Read` 같은 이상 현상이 발생하기 쉽습니다.
- 격리 수준이 높을수록 이상 현상은 줄어들지만 잠금과 충돌 비용이 증가합니다.
- 실무에서는 기본 격리 수준을 이해한 뒤, 필요한 경우에만 더 높은 격리 수준을 선택하는 것이 일반적입니다.
