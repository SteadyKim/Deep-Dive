# 프로세스와 쓰레드

## 개요

운영체제에서 프로그램이 실행되면 작업을 관리하기 위한 실행 단위가 필요합니다.  
이때 자원을 할당받는 기본 단위가 `프로세스`이고, 프로세스 내부에서 실제 실행 흐름을 나누는 단위가 `쓰레드`입니다.

두 개념은 모두 실행과 관련되어 있지만, **메모리를 어떻게 사용하고 자원을 어떻게 공유하는지**에서 큰 차이가 있습니다.  
이 차이를 이해하면 멀티태스킹, 동시성, 성능 최적화를 더 명확하게 볼 수 있습니다.

## 프로세스와 쓰레드 비교

| 구분 | 프로세스 | 쓰레드 |
| --- | --- | --- |
| 의미 | 실행 중인 프로그램 | 프로세스 내 실행 흐름의 단위 |
| 메모리 구조 | 독립된 주소 공간 보유 | 같은 프로세스의 메모리 일부 공유 |
| 자원 공유 | 기본적으로 다른 프로세스와 공유하지 않음 | Code, Data, Heap 공유 |
| 개별 자원 | 각자 Code, Data, Heap, Stack 보유 | 각자 Stack, Register 보유 |
| 통신 방식 | IPC 필요 | 같은 메모리 공간을 통해 비교적 쉽게 통신 |
| 안정성 | 한 프로세스 장애가 다른 프로세스에 직접 영향 적음 | 한 쓰레드 문제가 같은 프로세스 전체에 영향 가능 |
| 생성 비용 | 상대적으로 큼 | 상대적으로 작음 |

## 1. 프로세스

### 프로세스란 무엇인가

프로세스는 실행 중인 프로그램을 의미하며, 운영체제로부터 시스템 자원을 할당받는 작업 단위입니다.  
운영체제는 각 프로세스를 독립적으로 관리하기 위해 별도의 메모리 공간을 제공합니다.

### 프로세스의 메모리 구조

운영체제는 프로세스마다 독립된 메모리 영역을 할당하며, 일반적으로 다음과 같이 구분합니다.

- `Code`: 실행할 프로그램의 명령어가 저장되는 영역입니다.
- `Data`: 전역 변수와 정적 변수가 저장되는 영역입니다.
- `Heap`: 런타임에 동적으로 할당되는 데이터가 저장되는 영역입니다.
- `Stack`: 함수 호출 시 생성되는 지역 변수와 매개변수가 저장되는 영역입니다.

즉, 프로세스는 단순히 "실행 중"인 상태만을 뜻하는 것이 아니라, **코드와 데이터, 실행에 필요한 메모리 구조 전체를 포함한 독립 실행 환경**으로 볼 수 있습니다.

### 프로세스의 독립성

각 프로세스는 별도의 주소 공간을 가지므로 서로의 메모리에 직접 접근할 수 없습니다.  
이 때문에 한 프로세스가 비정상적으로 종료되더라도 다른 프로세스에 직접적인 영향을 주지 않는 경우가 많습니다.

이 독립성은 안정성 측면에서 큰 장점이지만, 반대로 프로세스끼리 데이터를 주고받으려면 추가 장치가 필요합니다.  
대표적으로는 다음과 같은 `IPC(Inter-Process Communication)` 방식이 사용됩니다.

- 파이프(Pipe)
- 메시지 큐(Message Queue)
- 공유 메모리(Shared Memory)
- 소켓(Socket)

즉, 프로세스는 안정적이지만, 서로 완전히 분리되어 있기 때문에 통신 비용이 상대적으로 큽니다.

## 2. 쓰레드

### 쓰레드란 무엇인가

쓰레드는 프로세스 내에서 실행되는 흐름의 단위입니다.  
하나의 프로세스는 최소 하나 이상의 쓰레드를 가지며, 여러 개의 쓰레드를 두면 하나의 프로세스 안에서 여러 작업을 동시에 처리할 수 있습니다.

예를 들어 웹 브라우저는 하나의 프로세스 안에서 화면 렌더링, 네트워크 통신, 사용자 입력 처리를 여러 쓰레드로 나누어 수행할 수 있습니다.

### 쓰레드의 자원 공유 구조

같은 프로세스에 속한 쓰레드들은 프로세스가 가진 자원을 공유합니다.

#### 공유하는 영역

- `Code`
- `Data`
- `Heap`

이 영역을 공유하기 때문에 같은 프로세스의 쓰레드들은 같은 데이터에 빠르게 접근할 수 있습니다.

#### 각자 가지는 영역

- `Stack`
- `Register`
- `Program Counter(PC)`

각 쓰레드는 독립적인 실행 흐름을 유지해야 하므로 함수 호출 스택과 CPU 실행 상태는 따로 가집니다.

### 쓰레드가 효율적인 이유

쓰레드는 프로세스보다 가볍습니다.  
같은 프로세스 안에서 동작하기 때문에 새로 큰 메모리 공간을 만들 필요가 없고, 이미 존재하는 자원을 공유할 수 있기 때문입니다.

그래서 일반적으로 다음과 같은 장점이 있습니다.

- 생성과 종료가 프로세스보다 빠릅니다.
- 문맥 교환(Context Switch) 비용이 상대적으로 낮습니다.
- 같은 메모리 공간을 공유하므로 통신 비용이 낮습니다.

이 특성 때문에 쓰레드는 병렬 처리나 동시성 처리가 필요한 프로그램에서 자주 사용됩니다.

### 쓰레드를 사용할 때의 주의점

쓰레드는 자원을 공유하므로 효율적이지만, 동시에 같은 데이터를 수정하면 동기화 문제가 발생할 수 있습니다.  
즉, 프로세스보다 빠르고 가볍다는 장점이 있는 대신 `Race Condition`, `Deadlock` 같은 동시성 문제가 생길 수 있습니다.

따라서 쓰레드는 효율성과 함께 `Mutex`, `Semaphore`, `Lock` 같은 동기화 기법을 함께 이해해야 제대로 사용할 수 있습니다.

## 정리

- `프로세스`는 운영체제로부터 자원을 할당받는 독립 실행 단위입니다.
- 프로세스는 `Code`, `Data`, `Heap`, `Stack`으로 구성된 독립된 메모리 공간을 가집니다.
- 각 프로세스는 독립적인 주소 공간을 가지므로 안정성이 높지만, 프로세스 간 통신에는 별도의 IPC가 필요합니다.
- `쓰레드`는 프로세스 내부의 실행 흐름 단위이며, 같은 프로세스의 `Code`, `Data`, `Heap`을 공유합니다.
- 각 쓰레드는 독립적인 실행을 위해 자신만의 `Stack`, `Register`, `PC`를 가집니다.
- 쓰레드는 프로세스보다 생성 비용과 통신 비용이 낮아 효율적이지만, 자원 공유로 인해 동기화 문제가 발생할 수 있습니다.

결국 프로세스는 **독립성과 안정성**, 쓰레드는 **효율성과 자원 공유**에 더 초점이 맞춰진 실행 단위라고 정리할 수 있습니다.
