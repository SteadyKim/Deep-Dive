# 메모리 계층 구조와 캐시

## 개요

CPU는 매우 빠르지만, 메인 메모리(RAM)는 그에 비해 훨씬 느립니다.  
만약 CPU가 모든 데이터를 매번 메인 메모리에서 직접 가져온다면, 빠른 CPU가 느린 메모리를 기다리느라 대부분의 시간을 낭비하게 됩니다.

이 속도 격차를 메우기 위해 컴퓨터는 여러 종류의 저장 장치를 속도와 용량에 따라 계층적으로 배치합니다.  
이것을 `메모리 계층 구조(Memory Hierarchy)`라고 하며, 그 핵심에는 CPU와 메인 메모리 사이에서 완충 역할을 하는 `캐시 메모리(Cache Memory)`가 있습니다.

이 문서는 왜 계층 구조가 필요한지, 캐시가 어떤 원리로 동작하며 어떤 설계 선택이 존재하는지를 정리합니다.

## 1. 왜 메모리 계층 구조가 필요한가

이상적인 메모리는 `빠르고`, `용량이 크고`, `저렴한` 것이지만, 현실에서는 이 세 가지를 동시에 만족할 수 없습니다.

- 빠른 메모리(SRAM)는 비싸고 용량을 크게 만들기 어렵습니다.
- 저렴하고 큰 메모리(HDD, SSD)는 느립니다.

그래서 컴퓨터는 하나의 완벽한 메모리 대신, **빠르고 작은 것부터 느리고 큰 것까지** 여러 층으로 쌓아 올리는 절충안을 택합니다.

| 계층 | 예시 | 속도 | 용량 | 관리 주체 |
| --- | --- | --- | --- | --- |
| 레지스터 | CPU 레지스터 | 가장 빠름 | 수십~수백 byte | 컴파일러 |
| 캐시 | L1 / L2 / L3 | 매우 빠름 | KB~수십 MB | 하드웨어 |
| 메인 메모리 | DRAM | 빠름 | 수 GB~수십 GB | 운영체제 |
| 보조 저장장치 | SSD / HDD | 느림 | 수백 GB~TB | 운영체제 |

위로 갈수록 빠르고 비싸며 용량이 작고, 아래로 갈수록 느리고 저렴하며 용량이 큽니다.  
각 계층은 바로 아래 계층의 데이터 중 자주 쓰이는 일부를 담아 두는 캐시 역할을 합니다.

## 2. 지역성(Locality)

메모리 계층 구조가 실제로 효과를 내는 이유는 프로그램의 메모리 접근 패턴이 무작위가 아니라 `지역성(Locality)`을 갖기 때문입니다.

### 시간 지역성(Temporal Locality)

한 번 접근한 데이터는 가까운 미래에 다시 접근될 가능성이 높습니다.

- 예: 반복문의 카운터 변수, 자주 호출되는 함수

### 공간 지역성(Spatial Locality)

한 번 접근한 데이터의 주변 주소도 곧 접근될 가능성이 높습니다.

- 예: 배열의 순차 순회, 코드의 순차 실행

이 두 성질 덕분에 최근 사용한 데이터와 그 주변을 빠른 계층에 올려 두면, 이후 접근의 상당수를 빠르게 처리할 수 있습니다.  
캐시가 데이터를 낱개가 아니라 `블록(캐시 라인)` 단위로 가져오는 것도 공간 지역성을 활용하기 위함입니다.

## 3. 캐시의 동작 원리

CPU가 특정 주소의 데이터를 요청하면, 먼저 캐시를 확인합니다.

- 원하는 데이터가 캐시에 있으면 `캐시 히트(Cache Hit)`: 빠르게 데이터를 반환합니다.
- 캐시에 없으면 `캐시 미스(Cache Miss)`: 메인 메모리에서 해당 블록을 읽어 캐시에 올린 뒤 반환합니다.

캐시의 효율은 `히트율(Hit Rate)`로 측정하며, 평균 접근 시간은 다음과 같이 표현할 수 있습니다.

```
평균 접근 시간 = (히트율 × 캐시 접근 시간) + (미스율 × 메모리 접근 시간)
```

히트율이 조금만 올라가도 평균 접근 시간이 크게 줄어들기 때문에, 캐시 설계의 핵심은 히트율을 높이는 것입니다.

## 4. 캐시 매핑 방식(Cache Mapping)

메인 메모리의 블록을 캐시의 어느 자리에 놓을지를 정하는 규칙이 `매핑 방식`입니다.  
세 가지 방식이 있으며, 각각 하드웨어 비용과 히트율 사이의 트레이드오프를 가집니다.

| 방식 | 배치 규칙 | 장점 | 단점 |
| --- | --- | --- | --- |
| 직접 매핑(Direct Mapped) | 블록마다 들어갈 자리가 하나로 고정 | 구현이 단순하고 조회가 빠름 | 특정 자리에 접근이 몰리면 충돌 미스 증가 |
| 완전 연관(Fully Associative) | 어느 자리에나 배치 가능 | 충돌 미스가 거의 없음 | 모든 자리를 비교해야 해 비용이 큼 |
| 집합 연관(Set Associative) | 여러 자리로 이뤄진 집합 안 어디든 배치 | 위 둘의 절충, 실무 표준 | 직접 매핑보다 복잡 |

실제 CPU 캐시는 대부분 `N-way 집합 연관(N-way Set Associative)` 방식을 사용합니다.  
예를 들어 4-way라면, 하나의 집합 안에 4개의 자리가 있어 그 안에서는 자유롭게 배치할 수 있어 충돌 미스를 줄이면서도 비교 비용을 감당할 수준으로 유지합니다.

## 5. 캐시 교체 정책과 쓰기 정책

### 교체 정책(Replacement Policy)

집합이 가득 찬 상태에서 새 블록을 올려야 하면, 기존 블록 중 하나를 내보내야 합니다.  
이때 어떤 블록을 버릴지 정하는 것이 교체 정책이며, 대표적으로 `LRU(Least Recently Used)`가 쓰입니다. 오래 사용되지 않은 블록일수록 앞으로도 쓰이지 않을 것이라는 지역성 가정에 기반합니다.

> 페이지 교체 알고리즘과 발상이 같지만, 캐시는 하드웨어가 나노초 단위로 처리해야 하므로 완전한 LRU 대신 이를 근사한 방식을 주로 사용합니다.

### 쓰기 정책(Write Policy)

CPU가 데이터를 쓸 때, 캐시와 메인 메모리의 값을 어떻게 일치시킬지에 대한 정책입니다.

| 정책 | 동작 | 트레이드오프 |
| --- | --- | --- |
| Write-Through | 캐시와 메모리에 동시에 쓴다 | 일관성이 단순하지만 쓰기가 느림 |
| Write-Back | 캐시에만 쓰고, 교체될 때 메모리에 반영 | 쓰기가 빠르지만 일관성 관리가 복잡 |

Write-Back은 변경된 블록을 표시하는 `Dirty Bit`를 두어, 교체 시 값이 바뀐 블록만 메모리에 다시 씁니다. 성능이 좋아 널리 쓰이지만, 멀티코어 환경에서는 캐시 간 일관성(Cache Coherence) 문제를 별도로 다뤄야 합니다.

## 정리

- 메모리는 속도·용량·비용을 모두 만족할 수 없어, `메모리 계층 구조`로 빠른 소량과 느린 대량을 계층적으로 결합합니다.
- 이 구조가 효과를 내는 근거는 프로그램의 `시간 지역성`과 `공간 지역성`입니다.
- `캐시`는 CPU와 메인 메모리 사이의 완충 장치로, `히트율`이 평균 접근 시간을 좌우합니다.
- 캐시 매핑은 `직접 매핑`, `완전 연관`, `집합 연관`이 있으며, 실무에서는 `N-way 집합 연관`이 표준입니다.
- 교체 정책은 `LRU 근사`, 쓰기 정책은 `Write-Through`와 `Write-Back`이 대표적입니다.

결국 메모리 계층 구조와 캐시의 핵심은 **지역성을 이용해 느린 저장 장치의 한계를 빠른 계층으로 가려, 적은 비용으로 빠른 평균 성능을 얻는 것**입니다.  
같은 알고리즘이라도 캐시를 고려해 데이터를 배치하느냐에 따라 실제 성능이 크게 달라집니다.
