# 인덱스를 통한 읽기보다 풀 테이블 스캔이 더 빠를 수 있는 이유

인덱스를 통해 데이터를 읽는 것보다 테이블 전체를 읽는 방식이 더 빠른 이유는, 결국 디스크 I/O의 물리적인 특성과 접근 방식의 차이 때문입니다.  
특히 인덱스를 통해 읽어야 할 데이터 비율이 전체의 약 10~15%를 넘어가기 시작하면, 하나씩 콕 집어서 읽는 방식보다 차라리 한 번에 쭉 읽는 풀 테이블 스캔이 더 효율적인 경우가 많습니다.

## 1. 싱글 블록 I/O와 멀티 블록 I/O의 차이

인덱스를 통해 데이터를 읽을 때는 일반적으로 **싱글 블록 I/O** 방식이 사용됩니다.  
즉, 인덱스 리프 블록에서 `ROWID`를 찾고, 그 주소를 따라가서 필요한 데이터 블록을 **한 번에 하나씩** 읽습니다.

예를 들어 10만 건의 데이터를 읽어야 한다면, 디스크에는 그만큼 많은 개별 요청이 발생할 수 있습니다.  
이 방식은 소량의 데이터를 정밀하게 찾을 때는 효율적이지만, 읽어야 할 데이터가 많아질수록 요청 횟수가 크게 늘어납니다.

반면 **풀 테이블 스캔**은 **멀티 블록 I/O** 방식을 사용합니다.  
한 번의 요청으로 인접한 여러 블록을 묶어서 읽어오기 때문에, 디스크에 요청하는 횟수 자체가 크게 줄어듭니다.

즉, 인덱스 스캔은 "필요한 것만 하나씩 집는 방식"이고, 풀 테이블 스캔은 "여러 블록을 트럭으로 한 번에 실어 나르는 방식"에 가깝습니다.  
읽을 데이터 양이 일정 수준을 넘어서면, 후자가 전체 비용 면에서 더 유리해집니다.

## 2. 랜덤 액세스와 순차 액세스의 속도 차이

인덱스 스캔은 기본적으로 **랜덤 액세스**입니다.  
인덱스가 가리키는 실제 테이블 데이터는 여기저기 흩어져 있을 수 있으므로, 디스크는 필요한 블록을 찾기 위해 이곳저곳 이동해야 합니다.

이 과정에서는 탐색 시간과 위치 이동 비용이 반복적으로 발생합니다.  
결국 읽어야 할 건수가 많아질수록 "찾아가는 비용"이 성능을 크게 떨어뜨립니다.

반대로 풀 테이블 스캔은 **순차 액세스**입니다.  
테이블이 저장된 물리적 순서에 따라 데이터를 연속적으로 읽어 들이기 때문에, 불필요한 이동이 적고 디스크 처리량을 더 잘 활용할 수 있습니다.

정리하면 다음과 같습니다.

- 인덱스 스캔: 필요한 데이터만 읽지만, 랜덤 액세스 비용이 큼
- 풀 테이블 스캔: 불필요한 데이터도 읽지만, 순차 액세스로 읽기 자체는 훨씬 빠름

그래서 읽어야 할 행 수가 많아질수록, 랜덤하게 여러 번 읽는 것보다 순서대로 한 번 훑는 편이 더 빨라질 수 있습니다.

## 3. 클러스터링 팩터가 나쁘면 중복 읽기 비용이 커진다

인덱스를 통해 찾은 행들이 테이블 블록에 정돈되어 모여 있으면 효율이 좋습니다.  
하지만 실제로는 조건에 맞는 행들이 여러 블록에 흩어져 있는 경우가 많습니다.

예를 들어 테이블 데이터가 100개 블록에 나뉘어 저장되어 있다고 가정하겠습니다.  
이때 전체의 10% 정도 행을 인덱스로 읽으려는데, 그 행들이 100개 블록 전체에 골고루 퍼져 있다면 상황이 달라집니다.

겉보기에는 10%만 읽는 것 같지만, 실제로는 거의 모든 블록을 한 번씩 방문해야 할 수 있습니다.  
심하면 같은 블록을 여러 번 다시 읽게 되는 비효율도 생깁니다.

반면 풀 테이블 스캔은 처음부터 끝까지 모든 블록을 한 번씩만 순서대로 읽으면 됩니다.  
이 경우 결과적으로 전체 블록 방문 비용이 인덱스 스캔보다 더 낮아질 수 있습니다.

이 차이를 크게 만드는 요소가 바로 **클러스터링 팩터**입니다.  
클러스터링 팩터가 나쁘다는 것은, 인덱스 순서와 실제 테이블 저장 순서가 잘 맞지 않는다는 뜻이고, 그만큼 인덱스 스캔의 랜덤 I/O 비용이 커진다는 의미입니다.

## 왜 보통 10~15%가 기준처럼 언급될까?

이 수치는 절대적인 법칙이라기보다, 옵티마이저가 접근 방식을 판단할 때 자주 언급되는 경험적 기준입니다.  
실제 임계점은 다음 요소들에 따라 달라집니다.

- 테이블 크기
- 인덱스 구조와 높이
- 클러스터링 팩터
- 멀티 블록 리드 성능
- 스토리지 특성
- 버퍼 캐시 적중률

즉, 어떤 환경에서는 5%만 넘어도 풀 테이블 스캔이 유리할 수 있고, 다른 환경에서는 20% 이상까지도 인덱스 스캔이 유지될 수 있습니다.  
하지만 핵심은 동일합니다. **읽어야 할 행이 많아질수록 인덱스의 장점은 줄고, 순차적으로 한꺼번에 읽는 방식의 장점은 커진다**는 점입니다.

## 정리

- 인덱스 스캔은 싱글 블록 I/O 중심이라 소량 조회에 유리합니다.
- 풀 테이블 스캔은 멀티 블록 I/O를 활용해 대량 조회에 유리합니다.
- 인덱스 스캔은 랜덤 액세스 비용이 크고, 풀 테이블 스캔은 순차 액세스라 처리량이 높습니다.
- 클러스터링 팩터가 나쁘면 인덱스 스캔의 실제 비용은 급격히 증가합니다.
- 그래서 읽어야 할 데이터 비율이 일정 수준을 넘으면, "필요한 것만 골라 읽는 방식"보다 "전체를 한 번에 훑는 방식"이 더 빨라질 수 있습니다.
