# 입출력 시스템과 DMA

## 개요

CPU와 메모리는 매우 빠르게 동작하지만, 키보드·디스크·네트워크 카드 같은 입출력 장치는 상대적으로 훨씬 느리고 동작 속도도 제각각입니다.  
운영체제는 이렇게 성격이 다른 수많은 장치를 다루면서도, 응용 프로그램에게는 `read()` / `write()`처럼 일관된 방식으로 보이게 만들어야 합니다.

이 문제를 해결하는 것이 `입출력(I/O) 시스템`입니다.  
핵심은 **느린 장치를 기다리느라 빠른 CPU가 놀지 않게 하는 것**이며, 그 정점에 있는 기법이 `DMA(Direct Memory Access)`입니다.  
이 문서는 CPU가 장치와 데이터를 주고받는 세 가지 방식과, 그 과정을 뒷받침하는 구조를 정리합니다.

## 1. 입출력 하드웨어의 구성

응용 프로그램이 장치에 직접 접근하지 못하는 것처럼, CPU도 장치의 물리적 신호를 직접 다루지 않습니다.  
그 사이에는 여러 계층이 존재합니다.

- `장치(Device)`: 실제 물리 장치 (디스크, 키보드, 네트워크 카드 등)
- `장치 컨트롤러(Device Controller)`: 장치를 제어하는 하드웨어. 내부에 레지스터와 버퍼를 가집니다.
- `장치 드라이버(Device Driver)`: 컨트롤러를 다루는 커널 내부의 소프트웨어. 장치마다 다른 세부 동작을 숨기고 커널에 일관된 인터페이스를 제공합니다.

CPU는 컨트롤러가 노출하는 레지스터를 읽고 쓰는 방식으로 장치와 통신합니다.

| 레지스터 | 역할 |
| --- | --- |
| 데이터 레지스터 | 주고받을 실제 데이터를 담습니다. |
| 상태 레지스터 | 장치가 바쁜지, 준비됐는지, 오류가 났는지를 나타냅니다. |
| 제어 레지스터 | CPU가 장치에 명령(읽기/쓰기 등)을 지시합니다. |

## 2. CPU가 컨트롤러에 접근하는 방법

CPU가 장치 컨트롤러의 레지스터를 지정하는 방식에는 두 가지가 있습니다.

- `고립형 입출력(Isolated I/O)`: 메모리 주소 공간과 별개의 `I/O 주소 공간`을 두고, 전용 입출력 명령어(`IN`, `OUT`)로 접근합니다.
- `메모리 맵 입출력(Memory-Mapped I/O)`: 장치 레지스터를 메모리 주소 공간의 일부에 매핑해, 일반 메모리 접근 명령어로 다룹니다.

메모리 맵 입출력은 별도의 입출력 명령어가 필요 없고 기존 메모리 접근 명령을 그대로 쓸 수 있어, 오늘날 대부분의 아키텍처가 채택합니다.

## 3. 입출력을 처리하는 세 가지 방식

같은 "장치에서 데이터를 읽어온다"는 작업도 CPU가 얼마나 개입하느냐에 따라 성능이 크게 달라집니다.

### 3.1 프로그램 입출력(Programmed I/O)

CPU가 상태 레지스터를 **반복해서 확인**하며 장치가 준비될 때까지 기다리는 방식입니다. 폴링(Polling) 기반입니다.

```
CPU: 장치 상태 확인 → 아직 안 됨 → 다시 확인 → ... → 준비됨 → 데이터 이동
```

- 구현이 단순합니다.
- 장치가 준비될 때까지 CPU가 `바쁜 대기(Busy Waiting)`에 갇혀 다른 일을 하지 못합니다.
- 느린 장치에 쓰면 CPU 낭비가 극심합니다.

### 3.2 인터럽트 기반 입출력(Interrupt-driven I/O)

CPU가 장치에 작업을 지시한 뒤 **다른 일을 하다가**, 장치가 준비되면 인터럽트로 알림을 받아 처리하는 방식입니다.

```
CPU: 읽기 명령 지시 → 다른 작업 수행
장치: 데이터 준비 완료 → 인터럽트 발생
CPU: 하던 일 멈추고 데이터 이동 → 원래 작업 복귀
```

- 바쁜 대기가 사라져 CPU 효율이 크게 올라갑니다.
- 하지만 **데이터를 실제로 옮기는 일은 여전히 CPU가** 합니다.
- 1바이트(또는 한 워드)마다 인터럽트가 발생하면, 대용량 전송 시 인터럽트 처리 오버헤드가 폭증합니다.

### 3.3 DMA(Direct Memory Access)

대용량 데이터 전송에서 "CPU가 데이터를 직접 나른다"는 마지막 병목을 없애는 방식입니다.  
`DMA 컨트롤러`라는 별도의 하드웨어가 CPU를 대신해 **장치와 메모리 사이에서 직접 데이터를 옮깁니다.**

## 4. DMA의 동작 원리

CPU는 전송의 시작과 끝에만 관여하고, 실제 데이터 이동은 DMA 컨트롤러에 위임합니다.

1. CPU가 DMA 컨트롤러에 전송 정보를 세팅합니다.
    - 전송 방향(읽기/쓰기)
    - 대상 메모리 주소
    - 전송할 데이터 크기(바이트 수)
2. CPU는 곧바로 다른 작업으로 돌아갑니다.
3. DMA 컨트롤러가 장치와 메모리 사이에서 데이터를 직접 전송합니다.
4. 지정한 크기의 전송이 **모두 끝나면** DMA 컨트롤러가 CPU에 인터럽트를 한 번 보냅니다.
5. CPU는 전송이 끝났음을 확인하고 후속 처리를 합니다.

```
[인터럽트 기반]  블록마다 CPU가 직접 이동 → 인터럽트 여러 번
[DMA]           DMA 컨트롤러가 블록 전체 이동 → 인터럽트 딱 한 번
```

핵심 차이는 **인터럽트 횟수**입니다. 인터럽트 기반은 데이터 단위마다 CPU를 부르지만, DMA는 전송이 끝날 때 한 번만 CPU를 부릅니다.

### 사이클 스틸링(Cycle Stealing)

DMA 컨트롤러와 CPU는 같은 `시스템 버스`와 메모리를 공유합니다.  
DMA가 메모리에 접근하는 동안에는 CPU가 그 버스를 쓸 수 없으므로, DMA는 버스가 비는 순간 짧게 끼어들어 데이터를 옮깁니다. 이를 `사이클 스틸링`이라고 합니다.

- CPU 입장에서는 메모리 접근이 아주 잠깐씩 지연되는 것처럼 보입니다.
- 그럼에도 CPU가 직접 데이터를 나르는 것보다 훨씬 효율적입니다.

## 5. 세 방식 비교

| 구분 | 프로그램 입출력 | 인터럽트 기반 입출력 | DMA |
| --- | --- | --- | --- |
| CPU의 대기 방식 | 바쁜 대기(폴링) | 대기 없음(다른 작업) | 대기 없음(다른 작업) |
| 데이터 이동 주체 | CPU | CPU | DMA 컨트롤러 |
| 인터럽트 횟수 | 없음 | 데이터 단위마다 | 전송 완료 시 1회 |
| CPU 부담 | 매우 큼 | 중간 | 작음 |
| 적합한 상황 | 단순·소량 전송 | 소량·간헐적 전송 | 디스크·네트워크 등 대용량 전송 |

## 6. 입출력 소프트웨어 계층과 버퍼링

운영체제는 장치의 다양성을 숨기기 위해 입출력을 여러 계층으로 나눕니다.

```
응용 프로그램  →  시스템 콜(read/write)
              →  커널 입출력 서브시스템 (버퍼링, 스케줄링, 캐싱)
              →  장치 드라이버
              →  장치 컨트롤러 → 장치
```

이 과정에서 성능을 좌우하는 대표적인 기법이 `버퍼링(Buffering)`입니다.

- `버퍼링`: 장치와 응용 프로그램의 **속도 차이**를 완충하기 위해 중간에 데이터를 임시로 모아 두는 기법입니다. 느린 장치가 데이터를 채우는 동안 응용 프로그램은 다른 일을 할 수 있습니다.
- `캐싱(Caching)`: 자주 쓰는 데이터를 메모리에 보관해 느린 장치 접근 자체를 줄입니다. 버퍼가 "옮기는 중인 데이터"를 담는다면, 캐시는 "재사용할 데이터"의 사본을 담는다는 점이 다릅니다.
- `스풀링(Spooling)`: 프린터처럼 여러 요청을 동시에 받을 수 없는 장치를 위해, 출력 데이터를 디스크에 순서대로 모아 두었다가 장치가 처리 가능한 만큼 순차적으로 내보냅니다.

## 정리

- 입출력 시스템은 느리고 다양한 장치를 다루면서도 응용 프로그램에는 일관된 인터페이스를 제공하며, 핵심 목표는 **느린 장치 때문에 빠른 CPU가 놀지 않게 하는 것**입니다.
- CPU는 `장치 컨트롤러`의 레지스터를 통해 장치와 통신하며, 접근 방식으로는 `메모리 맵 입출력`이 널리 쓰입니다.
- 입출력 처리 방식은 `프로그램 입출력(폴링)` → `인터럽트 기반` → `DMA` 순으로 CPU 개입이 줄어듭니다.
- `DMA`는 DMA 컨트롤러가 장치와 메모리 사이에서 데이터를 직접 옮기고, 전송이 끝날 때 인터럽트를 한 번만 발생시켜 대용량 전송에서 CPU 부담을 크게 줄입니다.
- `버퍼링`·`캐싱`·`스풀링`은 장치와 응용 프로그램의 속도 차이를 완충하는 커널 입출력 서브시스템의 핵심 기법입니다.

결국 입출력 시스템의 핵심은 **CPU의 개입을 단계적으로 줄여 나가며, 느린 장치와 빠른 CPU가 서로를 기다리지 않고 동시에 일하게 만드는 것**입니다.
