# RAID

## 개요

`파일 시스템`이 하나의 디스크 위에 데이터를 어떻게 배치할지 다루고, `디스크 스케줄링`이 그 디스크의 I/O 요청 순서를 다룬다면,  
그 아래에는 또 다른 층위의 질문이 남습니다. **디스크 하나로는 부족한 성능과 안정성을 어떻게 확보할 것인가**입니다.

디스크 한 개는 근본적인 한계를 가집니다. 처리량은 그 디스크의 속도에 묶여 있고, 그 디스크가 고장 나면 데이터가 통째로 사라집니다.  
`RAID(Redundant Array of Independent Disks)`는 **여러 개의 물리 디스크를 묶어 하나의 논리 디스크처럼 보이게 만드는 기술**로, 이 두 문제를 함께 해결합니다.

핵심 아이디어는 두 가지입니다. 데이터를 여러 디스크에 나눠 **동시에 읽고 쓰는 것(성능)**, 그리고 일부 정보를 중복 저장해 **디스크가 죽어도 복구할 수 있게 하는 것(안정성)**입니다.  
RAID의 여러 레벨은 결국 이 성능과 안정성, 그리고 비용 사이에서 어디에 무게를 두느냐의 차이입니다.


## 1. RAID 관련 개념

### 스트라이핑

`스트라이핑`은 하나의 데이터를 일정 크기 블록(스트라이프)으로 쪼개 **여러 디스크에 분산 저장**하는 방식입니다.

```
데이터: [A][B][C][D][E][F]

Disk0: A  C  E
Disk1: B  D  F
```

- 큰 파일을 읽을 때 여러 디스크가 **동시에 자기 몫을 읽으므로** 처리량이 디스크 개수에 비례해 올라갑니다.
- 하지만 데이터가 여러 디스크에 흩어져 있어, **디스크 하나만 고장 나도 전체 데이터가 깨집니다.** 스트라이핑 자체는 안정성을 전혀 제공하지 않습니다.

### 미러링

`미러링`은 같은 데이터를 **두 개 이상의 디스크에 똑같이 복제**해 두는 방식입니다.

```
Disk0: A B C D
Disk1: A B C D   (완전 동일한 복사본)
```

- 한 디스크가 죽어도 나머지 복사본으로 즉시 서비스를 이어갈 수 있어 안정성이 높습니다.
- 대신 저장 용량의 절반(2중 미러 기준)을 복제본으로 써버려 **공간 효율이 낮습니다.**

### 패리티

`패리티`는 미러링처럼 데이터를 통째로 복제하는 대신, **XOR 연산으로 계산한 검증 값**을 별도로 저장해 두는 방식입니다.  
디스크 하나가 사라져도 남은 데이터와 패리티를 XOR하면 잃어버린 값을 되살릴 수 있습니다.

```
데이터 비트:  D0=1, D1=0, D2=1
패리티:       P = D0 ⊕ D1 ⊕ D2 = 0

D1 디스크가 고장 나 값을 잃었다면?
D1 = D0 ⊕ D2 ⊕ P = 1 ⊕ 1 ⊕ 0 = 0   → 원래 값 복구 성공
```

미러링이 용량 100%를 중복에 쓴다면, 패리티는 디스크 1개 분량만 검증 값에 쓰므로 **훨씬 공간 효율적**입니다.  
대신 쓰기가 일어날 때마다 패리티를 다시 계산해야 하는 **연산 비용**이 따라옵니다.

## 2. 주요 RAID 레벨

### RAID 0 (스트라이핑)

순수하게 스트라이핑만 적용한 방식입니다.

```
Disk0: A  C  E
Disk1: B  D  F
```

- **장점**: 읽기/쓰기 성능이 디스크 수에 비례해 최고 수준, 용량 손실 없음(전체 용량 사용).
- **단점**: 중복이 전혀 없어 디스크 1개만 고장 나도 전체 데이터 손실. 오히려 디스크가 많아질수록 **고장 확률은 커집니다.**
- **용도**: 성능이 절대적으로 중요하고 데이터가 사라져도 되는 경우(캐시, 임시 렌더링 작업 공간 등).

### RAID 1 (미러링)

두 디스크에 동일한 데이터를 복제합니다.

```
Disk0: A B C D
Disk1: A B C D
```

- **장점**: 한 디스크가 죽어도 무중단 운영, 복구가 단순(살아있는 쪽을 그대로 복사). 읽기는 두 디스크에서 분산 처리 가능.
- **단점**: 실제 사용 가능 용량이 전체의 절반. 비용 효율이 나쁩니다.
- **용도**: 용량보다 안정성과 단순함이 중요한 OS 부팅 디스크, 소규모 중요 데이터.

### RAID 5 (분산 패리티)

스트라이핑에 패리티를 더하되, 패리티를 **한 디스크에 몰지 않고 모든 디스크에 분산**시키는 방식입니다.  
최소 3개의 디스크가 필요합니다.

```
Disk0: A0  B0  P2
Disk1: A1  P1  C0
Disk2: P0  B1  C1

(P0 = A0⊕A1, P1 = B0⊕B1, ... 패리티가 대각선으로 분산됨)
```

- **장점**: 디스크 1개 고장까지 복구 가능하면서, 중복에 드는 용량은 디스크 1개분뿐이라 **공간 효율이 좋습니다.** (N개 중 N-1개 용량 사용)
- **단점**: 쓰기 시 패리티 재계산이 필요해 **쓰기 성능이 떨어집니다**(쓰기 페널티). 디스크 하나가 고장 난 상태에서 복구(rebuild)하는 동안 모든 디스크를 읽어야 하므로, 그 도중 두 번째 디스크가 죽으면 전체 손실입니다.
- **용도**: 용량 효율과 안정성의 균형이 필요한 일반 파일 서버.

### RAID 6 (이중 분산 패리티)

RAID 5와 구조는 같지만 **서로 다른 방식의 패리티를 2개** 저장합니다. 최소 4개의 디스크가 필요합니다.

- **장점**: 디스크 **2개가 동시에 고장 나도** 복구 가능. 대용량 디스크일수록 rebuild 시간이 길어져 그 사이 추가 고장 위험이 커지는데, RAID 6은 이 위험에 대비합니다.
- **단점**: 패리티를 2개 계산·저장하므로 쓰기 페널티가 RAID 5보다 크고, 용량 손실도 디스크 2개분입니다.
- **용도**: 대용량 디스크를 다수 사용하는 스토리지, 아카이빙 시스템.

### RAID 10 (1+0, 미러링 후 스트라이핑)

미러링(RAID 1)으로 안정성을 확보한 쌍들을 다시 스트라이핑(RAID 0)으로 묶는 방식입니다.

```
        [스트라이핑]
   ┌────────┴────────┐
 미러쌍1           미러쌍2
Disk0=Disk1      Disk2=Disk3
(A,C...)         (B,D...)
```

- **장점**: 스트라이핑의 높은 성능과 미러링의 빠른 복구를 동시에 확보. 패리티 계산이 없어 **쓰기 성능이 RAID 5/6보다 우수**합니다.
- **단점**: 용량 절반을 미러에 쓰므로 공간 효율이 낮습니다.
- **용도**: 쓰기가 빈번하면서 안정성도 필요한 데이터베이스 서버.

## 3. RAID 레벨 비교

| 레벨 | 최소 디스크 | 중복 방식 | 결함 허용 | 용량 효율 | 읽기 | 쓰기 |
| --- | --- | --- | --- | --- | --- | --- |
| RAID 0 | 2 | 없음 | 없음 | 100% | 매우 높음 | 매우 높음 |
| RAID 1 | 2 | 미러링 | 디스크 1개 | 50% | 높음 | 보통 |
| RAID 5 | 3 | 분산 패리티 | 디스크 1개 | (N-1)/N | 높음 | 낮음 |
| RAID 6 | 4 | 이중 패리티 | 디스크 2개 | (N-2)/N | 높음 | 더 낮음 |
| RAID 10 | 4 | 미러링+스트라이핑 | 각 미러쌍당 1개 | 50% | 매우 높음 | 높음 |

핵심 트레이드오프는 이렇게 정리됩니다.

- **RAID 0**: 안정성을 버리고 성능·용량을 얻는다.
- **RAID 1 / 10**: 용량을 버리고 안정성·성능을 얻는다.
- **RAID 5 / 6**: 쓰기 성능을 일부 희생해 용량 효율과 안정성을 함께 얻는다.

## 4. 실무에서 놓치기 쉬운 지점

### RAID는 백업이 아니다

RAID는 **디스크 하드웨어 고장**에 대비하는 기술이지, 데이터 자체를 보호하는 백업이 아닙니다.  
사용자가 파일을 실수로 지우거나, 랜섬웨어가 데이터를 암호화하거나, 파일 시스템이 손상되면 그 변경은 모든 디스크에 그대로 반영됩니다.  
따라서 RAID를 쓰더라도 별도의 백업은 반드시 필요합니다.

### 하드웨어 RAID vs 소프트웨어 RAID

| 구분 | 하드웨어 RAID | 소프트웨어 RAID |
| --- | --- | --- |
| 처리 주체 | 전용 RAID 컨트롤러 카드 | OS(예: Linux `mdadm`, ZFS, Windows 저장소 공간) |
| 성능 | 패리티 연산을 전용 칩이 처리 | CPU 자원을 소모 |
| 비용 | 컨트롤러 비용 발생 | 추가 하드웨어 불필요 |
| 이식성 | 같은 컨트롤러 없으면 복구 곤란 | OS만 있으면 이동 자유로움 |

현대에는 CPU 성능이 충분히 좋아지고 `ZFS`, `Btrfs` 같은 파일 시스템이 RAID 기능을 흡수하면서, 소프트웨어 RAID의 비중이 커지고 있습니다.

### 쓰기 페널티

RAID 5에서 데이터 블록 하나를 수정하려면 단순히 그 블록만 쓰면 되는 게 아닙니다.  
기존 데이터와 기존 패리티를 **읽어서**, 새 패리티를 계산한 뒤, 데이터와 패리티를 **각각 써야** 합니다(읽기 2번 + 쓰기 2번).  
이 때문에 작은 랜덤 쓰기가 많은 워크로드에서는 RAID 5/6이 RAID 10보다 크게 불리합니다.

### SSD 시대의 RAID

`디스크 스케줄링` 문서에서 SSD가 탐색 시간을 없애며 스케줄링 전제를 바꿨듯, RAID에도 변화가 있습니다.

- SSD는 개별 성능이 이미 매우 높아, 성능 목적의 스트라이핑 필요성이 상대적으로 줄었습니다.
- 반면 안정성 목적의 미러링·패리티는 여전히 유효합니다.
- 다만 패리티 RAID의 잦은 쓰기는 SSD의 **쓰기 수명**을 앞당길 수 있어, SSD에서는 미러링 계열이 선호되기도 합니다.

## 정리

- `RAID`는 여러 물리 디스크를 하나의 논리 디스크로 묶어 **성능(스트라이핑)**과 **안정성(미러링·패리티)**을 확보하는 기술입니다.
- `스트라이핑`은 성능을, `미러링`은 통째 복제로 안정성을, `패리티`는 XOR 검증 값으로 공간 효율적인 안정성을 제공합니다.
- `RAID 0`은 성능만, `RAID 1`은 안정성만, `RAID 5/6`은 용량 효율과 결함 허용의 균형, `RAID 10`은 성능과 안정성을 동시에 노립니다.
- 각 레벨의 선택은 결국 **성능·안정성·비용(용량)** 세 축 사이의 트레이드오프입니다.
- RAID는 하드웨어 고장 대비책일 뿐 **백업을 대체하지 않으며**, 쓰기 페널티와 SSD 마모 같은 실무적 고려가 함께 따라옵니다.

결국 RAID의 핵심은 **믿을 수 없는 개별 디스크 여러 개를, 하나의 더 빠르고 더 튼튼한 저장 장치로 추상화하는 것**입니다.  
어떤 레벨을 고르든 그 선택은 "무엇을 지키고 무엇을 포기할 것인가"라는 트레이드오프의 결과입니다.
