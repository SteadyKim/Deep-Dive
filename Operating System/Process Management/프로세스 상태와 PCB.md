# 프로세스 상태와 PCB

## 개요

프로세스는 태어나서 실행되고 끝날 때까지 하나의 상태에만 머무르지 않습니다.  
CPU를 기다리기도 하고, 실행되기도 하고, 디스크 I/O가 끝나기를 기다리며 멈춰 있기도 합니다.

운영체제는 수많은 프로세스가 이렇게 서로 다른 상태를 오가는 상황에서도 각 프로세스를 정확히 추적하고 제어해야 합니다.  
이를 위해 운영체제는 프로세스마다 `상태(State)`를 관리하고, 각 프로세스의 모든 정보를 `PCB(Process Control Block)`라는 자료구조에 담아 둡니다.

즉, **프로세스 상태**는 "지금 이 프로세스가 무엇을 하고 있는가"를 나타내고, **PCB**는 "그 프로세스를 다시 실행하려면 무엇을 기억해야 하는가"를 담는 그릇입니다.  
그리고 실행 중인 프로세스를 잠시 멈추고 다른 프로세스로 갈아타는 과정이 `컨텍스트 스위칭(Context Switch)`이며, 이 과정의 핵심 대상이 바로 PCB입니다.

## 1. 프로세스 상태

### 상태가 필요한 이유

CPU는 한순간에 하나의 프로세스만 실행할 수 있지만, 시스템에는 실행되기를 기다리는 프로세스가 여럿 존재합니다.  
어떤 프로세스는 당장 CPU만 주면 실행될 수 있고, 어떤 프로세스는 디스크에서 데이터가 올라오기를 기다리는 중이라 CPU를 줘도 할 일이 없습니다.

운영체제가 이 둘을 구분하지 못하면, CPU를 기다림만 하는 프로세스에게 넘겨 자원을 낭비하게 됩니다.  
그래서 운영체제는 프로세스를 **상태로 분류**해, 지금 CPU를 줄 수 있는 프로세스와 아직 줄 수 없는 프로세스를 명확히 나눕니다.

### 대표적인 5가지 상태

일반적으로 프로세스는 다음 5가지 상태로 설명합니다.

| 상태 | 의미 |
| --- | --- |
| `New` | 프로세스가 생성되고 있는 단계입니다. 아직 실행 준비가 끝나지 않았습니다. |
| `Ready` | 실행에 필요한 모든 준비가 끝나고, CPU 할당만 기다리는 상태입니다. |
| `Running` | CPU를 할당받아 실제로 명령어를 실행 중인 상태입니다. |
| `Waiting` | I/O 완료나 특정 이벤트를 기다리며 실행을 멈춘 상태입니다. `Blocked`라고도 합니다. |
| `Terminated` | 실행이 끝나 종료된 상태입니다. |

여기서 핵심은 `Ready`와 `Waiting`의 차이입니다.

- `Ready`는 **CPU만 주면 바로 실행 가능한** 상태입니다.
- `Waiting`은 **CPU를 줘도 할 일이 없는** 상태입니다. 기다리던 이벤트가 끝나야 비로소 다시 실행 후보가 됩니다.

스케줄러가 다음 실행 대상을 고를 때 대상으로 삼는 것은 오직 `Ready` 상태의 프로세스뿐입니다.

### 상태 전이

프로세스는 정해진 규칙에 따라 상태를 옮겨 다닙니다.

```
        admit              dispatch
 New ----------> Ready ---------------> Running -----> Terminated
                   ^                       |    exit
                   |   timeout / preempt   |
                   +-----------------------+
                   |                       |
                   |  I/O 완료 등 이벤트    | I/O 요청 등
                   +------ Waiting <-------+
```

각 전이의 의미는 다음과 같습니다.

- `New → Ready` (admit): 생성이 끝나고 실행 큐에 들어갑니다.
- `Ready → Running` (dispatch): 스케줄러가 선택하고 디스패처가 CPU를 넘깁니다.
- `Running → Ready` (timeout/preempt): 할당 시간을 다 쓰거나 더 높은 우선순위 작업에 CPU를 빼앗깁니다.
- `Running → Waiting`: I/O나 이벤트를 기다리기 위해 스스로 CPU를 내려놓습니다.
- `Waiting → Ready`: 기다리던 I/O나 이벤트가 완료되어 다시 실행 후보가 됩니다.
- `Running → Terminated` (exit): 작업을 마치고 종료됩니다.

주목할 점은 `Waiting`에서 곧바로 `Running`으로 가지 않는다는 것입니다.  
I/O가 끝나면 일단 `Ready`로 돌아가 다시 CPU 할당을 기다립니다. CPU를 누구에게 줄지는 항상 스케줄러가 결정하기 때문입니다.  
CPU 할당 규칙 자체는 [CPU 스케줄링](CPU%20스케줄링.md) 문서에서 더 자세히 다룹니다.

### 보류 상태(Suspended)

메모리가 부족하면 운영체제는 일부 프로세스를 통째로 디스크(스왑 공간)로 내보내기도 합니다.  
이렇게 메모리에서 빠져나가 잠시 멈춘 상태를 `보류(Suspended)` 상태라고 하며, 보통 두 가지로 나눕니다.

- `Suspended Ready`: 준비는 됐지만 메모리에서 내려가 대기하는 상태입니다.
- `Suspended Waiting`: 이벤트를 기다리는 채로 메모리에서 내려간 상태입니다.

즉, 보류 상태는 "CPU를 기다리는가"의 축과 "메모리에 올라와 있는가"의 축이 결합된 개념입니다.  
메모리와 스왑의 관계는 [가상 메모리](../Memory%20Management/가상%20메모리.md) 문서의 스왑 설명과 이어집니다.

## 2. PCB(Process Control Block)

### PCB란 무엇인가

`PCB`는 운영체제가 하나의 프로세스를 관리하기 위해 필요한 모든 정보를 담아 두는 자료구조입니다.  
프로세스가 생성되면 운영체제는 그 프로세스를 위한 PCB를 만들고, 프로세스가 종료되면 PCB도 함께 제거합니다.

쉽게 말하면 PCB는 프로세스의 **주민등록증이자 저장된 실행 상태**입니다.  
운영체제는 이 PCB만 보면 "이 프로세스가 누구이고, 어디까지 실행했으며, 다시 실행하려면 무엇을 복원해야 하는지"를 알 수 있습니다.

### PCB가 담는 정보

PCB에는 보통 다음과 같은 정보가 들어갑니다.

| 항목 | 설명 |
| --- | --- |
| 프로세스 식별자 | `PID` 등 프로세스를 구분하는 고유 번호입니다. |
| 프로세스 상태 | `Ready`, `Running`, `Waiting` 등 현재 상태입니다. |
| 프로그램 카운터(PC) | 다음에 실행할 명령어의 주소입니다. |
| CPU 레지스터 | 실행 중이던 레지스터 값들입니다. 재개 시 그대로 복원해야 합니다. |
| 스케줄링 정보 | 우선순위, 스케줄링 큐 포인터 등입니다. |
| 메모리 관리 정보 | 페이지 테이블, 베이스/리밋 레지스터 등 주소 공간 정보입니다. |
| I/O 상태 정보 | 할당된 I/O 장치, 열린 파일 목록 등입니다. |
| 계정 정보 | 사용한 CPU 시간, 실행 시간 제한 등입니다. |

특히 `프로그램 카운터`와 `CPU 레지스터`가 중요합니다.  
프로세스가 CPU를 빼앗겼다가 나중에 다시 실행될 때, 이 값들을 정확히 복원해야 **아무 일도 없었던 것처럼** 이어서 실행할 수 있기 때문입니다.

프로세스가 사용하는 `Code`, `Data`, `Heap`, `Stack` 메모리 구조 자체는 PCB에 직접 담기보다, PCB가 그 위치 정보를 가리키는 형태로 관리됩니다. 메모리 구조는 [프로세스와 쓰레드](프로세스와%20쓰레드.md) 문서를 참고하면 좋습니다.

### PCB는 어디에 저장되는가

PCB는 사용자 프로세스가 함부로 건드리면 안 되는 정보이므로, 운영체제가 관리하는 **커널 영역**에 저장됩니다.  
운영체제는 모든 프로세스의 PCB를 목록이나 테이블 형태로 관리하며, 상태별 큐(예: Ready Queue, Waiting Queue)는 실제로 PCB들을 연결한 구조로 구현되는 경우가 많습니다.

## 3. 컨텍스트 스위칭

### 컨텍스트 스위칭이란 무엇인가

`컨텍스트 스위칭(Context Switch)`은 CPU가 현재 실행 중인 프로세스를 멈추고 다른 프로세스를 실행하도록 전환하는 과정입니다.  
여기서 `컨텍스트(Context)`란 프로세스를 이어서 실행하는 데 필요한 상태 전체, 즉 PCB에 저장되는 정보들을 의미합니다.

전환은 크게 두 단계로 이루어집니다.

1. **저장**: 현재 실행 중이던 프로세스의 레지스터, 프로그램 카운터 등을 그 프로세스의 PCB에 저장합니다.
2. **복원**: 다음에 실행할 프로세스의 PCB에서 값을 읽어 CPU 레지스터에 복원합니다.

이 과정이 끝나면 CPU는 새 프로세스가 이전에 멈췄던 지점부터 실행을 이어갑니다.

### 언제 발생하는가

컨텍스트 스위칭은 다음과 같은 상황에서 일어납니다.

- 실행 중인 프로세스가 할당 시간을 모두 써서 `Running → Ready`로 밀려날 때
- 더 높은 우선순위 프로세스에 CPU를 빼앗길 때(선점)
- 실행 중인 프로세스가 I/O를 요청해 `Waiting` 상태로 들어갈 때
- 인터럽트가 발생해 운영체제가 개입해야 할 때

### 왜 비용이 문제인가

컨텍스트 스위칭이 진행되는 동안 CPU는 **사용자 작업을 전혀 수행하지 못합니다**.  
오로지 상태를 저장하고 복원하는 관리 작업만 하기 때문에, 이 시간은 순수한 오버헤드입니다.

- 스위칭이 너무 잦으면: 관리 비용이 커져 실제 작업 처리량이 떨어집니다.
- 스위칭이 너무 드물면: 응답성이 나빠지고 특정 작업이 오래 기다릴 수 있습니다.

여기에 더해, 프로세스를 전환하면 캐시나 TLB에 쌓여 있던 이전 프로세스의 정보가 무효화되어, 새 프로세스는 한동안 캐시 미스를 겪으며 느려질 수 있습니다.  
이 **간접 비용**까지 포함하면 컨텍스트 스위칭의 실제 부담은 단순한 저장/복원 시간보다 큽니다.

### 프로세스 전환과 쓰레드 전환

같은 프로세스에 속한 쓰레드끼리 전환하면 주소 공간이 그대로 유지되므로, 페이지 테이블 교체 같은 무거운 작업이 필요 없습니다.  
그래서 같은 프로세스 내 쓰레드 간 전환은 프로세스 간 전환보다 일반적으로 더 가볍습니다.  
이는 [프로세스와 쓰레드](프로세스와%20쓰레드.md) 문서에서 쓰레드가 프로세스보다 문맥 교환 비용이 낮다고 설명한 이유이기도 합니다.

## 4. 모드 전환과의 구분

컨텍스트 스위칭과 자주 혼동되는 개념이 `모드 전환(Mode Switch)`입니다.

- `모드 전환`: 같은 프로세스가 `사용자 모드`와 `커널 모드`를 오가는 것입니다. 시스템 콜이나 인터럽트 처리 시 발생하며, **실행 주체는 그대로**입니다.
- `컨텍스트 스위칭`: 실행되는 **프로세스 자체가 바뀌는** 것입니다.

모든 컨텍스트 스위칭은 커널 개입이 필요하므로 모드 전환을 동반하지만, 모드 전환이 항상 컨텍스트 스위칭으로 이어지는 것은 아닙니다.  
예를 들어 시스템 콜을 호출해 커널 모드로 들어갔다가 같은 프로세스로 다시 돌아오면, 모드 전환만 일어나고 컨텍스트 스위칭은 없습니다.

## 5. 실무 관점에서의 프로세스 상태

리눅스에서 `ps`나 `top` 명령으로 프로세스를 보면 상태가 문자로 표시되는데, 앞서 설명한 상태 모델과 대응됩니다.

| 표시 | 의미 | 상태 모델 대응 |
| --- | --- | --- |
| `R` | 실행 중이거나 실행 준비됨 | `Running` / `Ready` |
| `S` | 인터럽트 가능한 대기(이벤트 대기) | `Waiting` |
| `D` | 인터럽트 불가능한 대기(주로 디스크 I/O) | `Waiting` |
| `T` | 중단됨(stop 신호 등) | 보류/중단 |
| `Z` | 좀비. 종료됐지만 부모가 회수하지 않음 | `Terminated` 직후 |

특히 `Z(좀비)` 상태는 자식 프로세스가 종료됐는데 부모가 종료 상태를 회수(`wait`)하지 않아, PCB가 회수되지 못하고 남은 경우입니다.  
좀비가 쌓이면 PID 자원이 고갈될 수 있으므로, 부모 프로세스가 자식의 종료를 제대로 처리하는 것이 중요합니다.

`D` 상태로 오래 멈춰 있는 프로세스는 보통 느리거나 응답 없는 디스크/네트워크 I/O를 기다리는 경우이며, 신호로도 잘 종료되지 않아 시스템 문제를 진단할 때 중요한 단서가 됩니다.

## 정리

- 프로세스는 `New`, `Ready`, `Running`, `Waiting`, `Terminated` 상태를 오가며, 스케줄러의 선택 대상은 오직 `Ready` 상태입니다.
- `Ready`는 CPU만 주면 실행 가능한 상태, `Waiting`은 CPU를 줘도 할 일이 없는(이벤트 대기) 상태라는 점이 핵심 차이입니다.
- `PCB`는 프로세스 식별자, 상태, 프로그램 카운터, 레지스터, 메모리·I/O 정보 등을 담는 자료구조로, 커널 영역에서 관리됩니다.
- `컨텍스트 스위칭`은 실행 중인 프로세스의 상태를 PCB에 저장하고 다음 프로세스의 상태를 복원하는 과정이며, 그 자체는 순수한 오버헤드입니다.
- `모드 전환`은 같은 프로세스가 사용자/커널 모드를 오가는 것으로, 프로세스가 바뀌는 컨텍스트 스위칭과는 구분됩니다.

결국 프로세스 상태와 PCB는 **운영체제가 여러 프로세스를 중단하고 재개하면서도 각 프로세스를 정확히 이어서 실행할 수 있게 하는 토대**입니다.  
이 구조가 있기에 CPU 스케줄링과 멀티태스킹이 안정적으로 동작할 수 있습니다.
